# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated by the build brief: plain static HTML, CSS, and JavaScript suitable for GitHub Pages.

## Users

Dad's Moving & Storage stakeholders reviewing an AI-SEO proposal in a browser. They need to compare the current live-site state with proposed technical, schema, and content changes without touching the production website.

## Product Purpose

Provide an internal-review clone of dadsmoving.com that preserves the recognisable live-site experience while making every proposed SEO change explicit, navigable, and inspectable.

## Positioning

The review combines a real current-site mirror, page-level change states, inline rationale, valid structured data, and a complete Manila office-relocation topic cluster in one shareable static artifact.

## Operating Context

Reviewers open a public GitHub Pages URL, begin at a dedicated review index, follow links into mirrored or proposed pages, and toggle AI-SEO/audit notes globally.

## Capabilities and Constraints

- Never modifies dadsmoving.com, its WordPress installation, FTP, DNS, or hosting.
- Every page is marked UNCHANGED, RESTRUCTURED, or NEW.
- All pages carry `noindex,nofollow`; root `robots.txt` disallows all crawling.
- Pricing and timelines without operations-team confirmation are labelled illustrative samples.
- The live site's flagged AI-heavy blog copy and broken third-party widget remain unchanged and are only annotated.
- Deployment target is a public GitHub Pages project repository under bpaje.

## Brand Commitments

Preserve Dad's Moving & Storage's existing name, logo, visual identity, photographic assets, and practical, reassuring service voice. New review UI is additive and visually distinct from client-facing content.

## Evidence on Hand

- Current live pages and sitemap at https://dadsmoving.com
- Approved office-moves strategy in the adjacent client folder
- Existing website copy and SEO audit in the adjacent client folder
- Previously reviewed international, inbound, FAQ, schema, and `llms.txt` copy in `dads-moving-ai-seo-prototype.html`
- Existing logo and photography folders in the adjacent client folder

## Product Principles

- Preserve before-state fidelity before adding proposal layers.
- Make scope and rationale visible without confusing proposal notes with site copy.
- Prefer concrete Manila building, traffic, compliance, and move-day details over generic claims.
- Keep every page internally linked and independently reviewable.
- Treat crawl prevention and noindex coverage as release requirements.

## Accessibility & Inclusion

Review controls must work with keyboard and screen readers, use visible focus, maintain readable contrast, and remain usable at mobile widths.
